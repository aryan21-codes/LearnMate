1. Executive Summary & Problem Space

Online education currently suffers from an efficacy chasm: pre-recorded video lectures lack conversational adaptability, traditional text chatbots fail to maintain student engagement, and generic AI interfaces hallucinate without reference grounding.

LearnMate Live bridges this gap by engineering an active, multimodal virtual study room that behaves like an elite private tutor. It synthesizes real-time live video presence, intelligent audio streaming, synchronized illustrative whiteboard diagrams, autonomous educational video walkthroughs, and strict PDF document citations into an adaptive, misconception-aware learning environment.

Key Architectural Pillars

1. Multimodal Study Room
Combines Zoom Video SDK WebAssembly canvas with an AI Tutor conversation stream, interactive Smart Whiteboard, and Push-to-Talk audio channel.
2. Hybrid Lexical-Semantic RAG
Extracts and chunks user-uploaded study notes (PDFs) with PyMuPDF, scoring relevance using 72% Cosine Vector Similarity + 28% BM25 Lexical overlap.
3. Dynamic Mermaid Auto-Repair
Two-tiered client/server AST sanitizer that repairs LLM syntax quirks (unicode arrows, unquoted labels with symbols) into guaranteed-valid visual flowcharts.
4. Autonomous AI Video Explainer
Generates 3Blue1Brown/Khan Academy-style sequential animated storyboard scripts with synchronized SpeechSynthesis voiceover and timeline scrubbing.
5. Misconception Engine & Mastery
Detects flawed student mental models, dynamically shifts pedagogical strategies (Analogy -> Trace -> Socratic), and tracks granular mastery (0-100%).
6. Open-Material Topic Indexing
Eliminates mandatory single-topic constraints. Students can upload lecture notes and seamlessly ask questions across any chapter or concept in the material.

Security Architecture

  • Zero Client Credential Leakage: Zoom SDK Secret (`ZOOM_SDK_SECRET`) and Groq API Key (`OPENAI_API_KEY`) reside exclusively in backend environment variables. The browser receives short-lived, session-scoped cryptographic signatures.
  • HMAC-SHA256 JWT Generation: Zoom Video SDK tokens are created on-demand via server-side cryptographic signing with strict 48-hour epoch expirations and randomized channel nonces.
  • Sandboxed Document Storage: Uploaded PDFs are assigned UUIDv4 identifiers and stored in isolated storage directories with sanitization against path-traversal attacks.

3. Deep Dive: Key Technical Subsystems

3.1 Dual-Channel Audio & Mic Contention Resolution

A critical engineering challenge in browser-based live tutoring is Microphone Contention: web browsers permit only one active WebRTC or audio capture context at a time. If Zoom Video SDK acquires the student's microphone, concurrent native browser speech recognition (`webkitSpeechRecognition`) crashes or fails silently.

The Browser Audio Lockout Problem
Running Zoom audio streaming while simultaneously listening for AI tutor voice prompts causes audio track collisions, browser mic locks, or echo loops when the tutor speaks aloud.

LearnMate Live solves this through an architectural Audio Input Manager supporting three distinct operational modes:

  1. Push-to-Talk Mode (Recommended Default): When the student presses and holds the mic button, the system temporarily acquires a clean MediaStream, streams audio or invokes recognition, and immediately releases the hardware audio track upon key release. This prevents any contention with Zoom audio.
  2. Zoom SDK Audio Mode: The student relies entirely on the Zoom WebAssembly audio channel. Transcriptions are generated server-side via Groq Whisper (`/api/tutor/transcribe-audio`).
  3. Chromium Speech Keep-Alive Heartbeat: Modern Chromium browsers aggressively garbage-collect long-running `SpeechSynthesisUtterance` objects after ~15 seconds, abruptly cutting off the tutor's voice mid-sentence. We implemented a 4-second keep-alive heartbeat calling `window.speechSynthesis.resume()` and anchored the active utterance to `window.__activeTutorUtterance` to guarantee continuous, uninterrupted narration.

3.2 Hybrid Lexical-Semantic PDF RAG Pipeline

Rather than relying on basic string matching or uncalibrated vector databases, LearnMate Live implements a bespoke hybrid retrieval algorithm optimized for educational textbooks:

def retrieve_relevant_chunks(query, document_ids, top_k=4):
    chunks = db.get_chunks_for_documents(document_ids)
    query_tokens = _WORD_RE.findall(query.lower())
    query_emb = _generate_embeddings([query])[0]
    
    for c in chunks:
        # 1. Lexical BM25 Overlap (Term Frequency / Normalized Document Length)
        lex_score = compute_lexical_overlap(query_tokens, c["content"])
        
        # 2. Semantic Cosine Vector Similarity
        sem_score = cosine_similarity(query_emb, c["embedding"])
        
        # 3. Hybrid Weighted Score
        composite_score = 0.72 * sem_score + 0.28 * lex_score
        
    return top_chunks_sorted_by_composite_score

Page Grounding & Direct Citations: Every chunk retains its originating PDF page number and document name. When the AI tutor answers, it explicitly cites sources (e.g., [Source 1: Biology_Ch3.pdf, Page 14]), rendering clickable citation badges in the student's References drawer.

4. Visual & Video Systems Architecture

4.1 Dynamic Mermaid Whiteboard & Auto-Repair Engine

Large Language Models excel at reasoning but frequently produce slightly malformed Mermaid.js flowchart syntax that crashes browser SVG renderers. Common issues include unicode arrow variations (`⟶`), unquoted labels with parentheses (e.g. A[Call fact(4)]), and conversational preamble text.

We built an autonomous two-tiered AST repair pipeline executed both on the FastAPI backend and in the React client:

  • Preamble Stripping: Scans input lines to locate standard diagram declarations (flowchart TD, graph TD, sequenceDiagram), discarding conversational lead-in prose.
  • Arrow Normalization: Normalizes unicode symbols (→, ⟶, ➔) and single dashes (->) into strictly conforming Mermaid syntax (-->).
  • Universal Label Sanitizer: Automatically detects unquoted content containing operators, parentheses, or chemical superscripts (e.g., Li+, fact(4), e-) using !/^[A-Za-z0-9_ ]+$/ and safely encapsulates them in double quotes.
  • DOM ID Collision Prevention: Generates unique cryptographic IDs for every render pass (lm_diag_${reactId}_${Date.now()}...), completely eliminating SVG marker clipping and DOM cache collisions.
  • Responsive SVG Box-Model Fix: Enforces w-full h-auto max-h-[440px] to prevent Chromium flexbox containers from collapsing diagrams to 0px height.

5. Adaptive Pedagogy & Open-Topic Learning

5.1 Misconception Detection & Strategy Switching

When a student submits an incorrect or incomplete answer during evaluation checks, LearnMate Live does not simply say "incorrect". The AI diagnostic engine executes a 3-step intervention:

  1. Root Cause Identification: Pinpoints the exact misconception (e.g., "Treating recursion like a flat loop without accounting for call stack memory").
  2. Pedagogical Strategy Pivot: Automatically switches from the failed strategy to a contrasting method (e.g., switching from Analogy First to Step-by-Step Call Stack Trace).
  3. Adaptive Dynamic Explanation: Re-explains the concept from first principles using the new strategy, accompanied by an updated visual whiteboard diagram.

5.2 Open-Material Topic Indexing

Unlike traditional tutoring systems that force students to choose a single narrow topic upfront, LearnMate Live supports Open-Material Study:

  • Topic is Optional: Students can leave the topic input blank. LearnMate automatically sets the scope to "All Topics in [Document Name]" or "Comprehensive Review".
  • Cross-Chapter Inquiries: The RAG engine indexes every page of the uploaded notes. A student can ask about Chapter 1 (e.g., "What is an electrochemical anode?") and immediately pivot to Chapter 4 (e.g., "How does QLED quantum dot emission compare?").
  • Dynamic Concept Tagging: The LLM dynamically extracts the underlying sub-concept for each turn, ensuring knowledge mastery records accurately track student strengths across every concept covered.

5.3 Database Architecture (SQLite3 WAL)

The system utilizes seven normalized relational tables in SQLite3 with Write-Ahead Logging for high concurrency:

  • users: Student profiles, study preferences, and registration timestamps.
  • tutor_sessions: Active and past study rooms, Zoom session names, duration, and document mappings.
  • session_messages: Full conversational audit log including tutor explanations, diagrams, and citations.
  • study_documents: Uploaded PDF metadata, file paths, page counts, and parsing status.
  • document_chunks: Extracted text passages, page numbers, and vector embeddings.
  • user_mastery: Continuous tracking of concept scores (0-100%), attempt counts, and misconception logs.
  • session_insights: Post-session AI summaries, demonstrated strengths, and targeted recommendations.
